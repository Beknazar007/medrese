# Конвейер агентов

Аргументы: `$ARGUMENTS`. Первое слово — `<feature>` (латиница, kebab-case), остальное — описание (только для новой фичи).

Субагенты не могут вызывать друг друга, поэтому связь держится на двух вещах:
- **файл состояния** `pipeline/<feature>.json` — каждый агент читает его в начале и дописывает в конце (что сделал, какие файлы, кто следующий);
- **этот навык** — главная сессия читает файл и сама запускает следующего агента (`Agent` с `subagent_type` = имя агента), пока не упрётся в ворота человека.

## Файл состояния

```json
{
  "feature": "excuse-photos",
  "title": "Фото справки к освобождению",
  "branch": "feature/excuse-photos",
  "next": "architect",
  "waiting_for": null,
  "review_iteration": 0,
  "version": null,
  "artifacts": {
    "spec": "specs/excuse-photos.md",
    "plan": null, "review": null, "e2e": [], "user_guide": [],
    "scenario": null, "videos": null
  },
  "history": [
    {"agent": "pm", "at": "2026-11-10T14:05+06:00", "result": "спека-черновик", "next": "architect"}
  ]
}
```

`waiting_for` — какие ворота ждут человека: `spec_approval` | `pr_merge` | `tag_confirm` | `video_approval` | `human_decision` | `null`.

## Переходы

| Закончил | Результат | Следующий шаг |
|---|---|---|
| — (новая фича) | | создать файл, `next: pm` |
| pm | спека-черновик | ворота `spec_approval` → architect |
| architect | план | developer |
| developer | код и тесты | reviewer (`review_iteration` + 1) |
| reviewer | одобрено | qa |
| reviewer | замечания, итерация < 3 | developer |
| reviewer | замечания, итерация = 3 | ворота `human_decision` |
| qa | баги | developer (затем снова reviewer) |
| qa | всё зелёное | ворота `pr_merge` → release |
| release | версия и CHANGELOG | ворота `tag_confirm` → publisher (режим 2) |
| publisher (режим 2) | список устаревших видео | docs |
| docs | инструкция обновлена | video-scriptwriter |
| video-scriptwriter | сценарий | video-producer |
| video-producer | видео | publisher (режим 1: только регистрация) |
| publisher (регистрация) | записи `draft` | ворота `video_approval` → publisher (режим 1: публикация) |
| publisher (публикация) | опубликовано | `next: done` |

## Как проверять ворота

Ворота открывает только человек. Ты лишь проверяешь, открыты ли они, и **никогда не ставишь отметки сам**.

- `spec_approval` — в `specs/<feature>.md` есть строка `Статус: утверждено`.
- `pr_merge` — `git fetch origin` и `git merge-base --is-ancestor <branch> origin/main` возвращает 0.
- `tag_confirm` — тег `v<version>` существует (`git tag -l`). Если человек в этом разговоре явно написал «да» на команды тега — передай release «человек подтвердил тег», он выполнит команды; иначе жди.
- `video_approval` — у всех записей фичи в `videos/registry.json` стоит `"approved": true`, и нет `religious_review: "required"`.
- `human_decision` — человек сказал, что делать (продолжить ревью, принять как есть, отменить); запиши решение в `history`.

## Цикл

1. Прочитай `pipeline/<feature>.json`. Нет файла и есть описание — создай его (`next: pm`). Нет файла и нет описания — спроси, что за фича.
2. Если `waiting_for` не пусто — проверь ворота. Закрыты — остановись и скажи человеку одним абзацем, что именно ему сделать. Открыты — очисти `waiting_for`, допиши в `history` `{"agent": "human", "result": "<ворота> открыты"}`.
3. Запусти агента `next`. В промпт передай: путь к файлу состояния, `feature`, ветку, пути всех артефактов из `artifacts`, номер итерации ревью, режим publisher.
4. После ответа перечитай файл состояния. Если агент его не обновил — обнови сам по блоку «Передать дальше» из ответа. Сверь с таблицей переходов; если агент назвал другой следующий шаг — следуй таблице и запиши расхождение в `history`.
5. Повторяй 2–4, пока не дойдёшь до ворот или `done`.
6. В конце покажи человеку: пройденные этапы (по `history`), созданные файлы, где стоим и что нужно от него.

## Нельзя

- Ставить `Статус: утверждено`, `approved`, `religious_review: "approved"`, пушить, мержить, ставить тег без явного «да» в разговоре.
- Пропускать агента или ворота, даже если человек торопится, — сначала спроси.
- Передавать дальше фрагменты с `⚠ ТРЕБУЕТ ПРОВЕРКИ УСТАЗОМ` как готовые: напомни о них человеку на каждой остановке.

`/pipeline` без аргументов — покажи все `pipeline/*.json`: фича, `next`, `waiting_for`.
